org-roam-second-brainNotes you and an AI assistant both keep

Your notes stay plain org files. The vault says what each kind of note must have and what may change only with your approval; an MCP server inside Emacs gives an assistant 23 tools over the same notes, sized for small local models; and every write can be previewed and undone.

Install GitHub Guide Tools FAQ The story 
(use-package org-roam-second-brain
  :after org-roam
  :config
  (orsb-mode 1)        ; C-c b: the digest, new notes, the approval screen
  (orsb-mcp-start))    ; http://127.0.0.1:8007/mcp

What it is

  • The vault defines its types

    A folder is a note type when it holds a _schema.org: required properties, status values, starting sections. The package has no types of its own.

  • Rules on every write

    A section may only grow, be rewritten whole, or change by approval. A write that breaks a rule is reported, or refused in a folder marked strict.

  • Approval where you want it

    The assistant files the change with a reason. You see it line by line in Emacs and approve or reject it. Nothing is written until you do.

  • Every write can be undone

    Each one returns a change_id; restore puts every file it touched back. Most writes take a dry run.

  • Sized for small local models

    23 tools, one way to name a note, one answer shape, and a hint on every error. A test kit scores a model on nineteen everyday chores.

  • Nothing but Emacs

    The server is Emacs Lisp, inside your Emacs. No Python, no Node, no container. Search by meaning needs an embeddings endpoint, and is optional.

Install

Emacs 29.1 or newer and org-roam 2.2 or newer. With Doom Emacs, in packages.el:

(package! org-roam-second-brain
  :recipe (:host github :repo "dcruver/org-roam-second-brain"))

With straight.el, or Emacs's own package-vc:

(straight-use-package
 '(org-roam-second-brain :type git :host github :repo "dcruver/org-roam-second-brain"))

(package-vc-install "https://github.com/dcruver/org-roam-second-brain")

Then (orsb-mode 1). Each release says what it changed.

A note type is a text file you can read

Put this in projects/_schema.org and every note in that folder is a project, for you and for the assistant.

* Type
:PROPERTIES:
:TYPE: project
:LIFECYCLE: STATUS
:LIFECYCLE_VALUES: active waiting done
:LIFECYCLE_FINISHED: done
:END:

* Properties
| property    | required | form                    | default |
|-------------+----------+-------------------------+---------|
| STATUS      | yes      | one of LIFECYCLE_VALUES | active  |
| NEXT-ACTION | yes      | one sentence            |         |

* Sections
| section       | required | rule    |
|---------------+----------+---------|
| Current state | yes      | replace |
| Log           | yes      | append  |
| Decisions     | no       | propose |

Connect an assistant

Any MCP client that speaks Streamable HTTP. With Claude Code:

claude mcp add --transport http notes http://localhost:8007/mcp

The server tells the model how to behave when it connects, so there is no skill or prompt to install. The tools page lists what it can call.

Where it stands

Version 3. The tests run on Emacs 29 and 30. It has kept one vault so far, the author's, mostly through an assistant on a local model, so a vault laid out differently will find rough edges. The FAQ says what is missing, and an issue about your vault is welcome.
